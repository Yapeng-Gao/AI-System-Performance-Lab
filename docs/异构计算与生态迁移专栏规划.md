**本仓库的落地约定（建议）**：

- **文章**：`article/04_heterogeneous_migration/`
- **示例代码**：`examples/06_heterogeneous_migration/`
- **跨后端算子骨架**：`include/aspl/ops/` + `src/ops/` + `src/kernels/<backend>/`

**状态**：⏳ 规划中（建议先落地“最小可迁移算子库骨架 + 1 个算子双后端实现 + 统一 benchmark”作为专栏开篇工程主线。）

## 4. 对本仓库“代码架构完善”的直接贡献点（专栏驱动工程落地）

为了让这个仓库真正成为“专栏文章 + 代码讲解 + 可运行工程”，建议本专栏优先落地 3 个最关键的工程资产：

1. **统一的后端抽象与 Dispatch**
   - 在 `include/aspl/ops/` 定义稳定的 Host API（与后端无关）
   - 在 `src/ops/` 做 dispatch（CUDA/CANN/…）
2. **后端分目录的 kernels**
   - `src/kernels/cuda/`（已有）
   - `src/kernels/cann/`（建议补齐真实实现与示例）
3. **跨后端可比的 benchmark**
   - 用同一套输入/计时/指标定义，产出可对比的结果（落到 `docs/results/`）

这样专栏每推进一章，仓库就同步增强“可迁移、可验证、可复用”的工程价值。
