# A-04. 线程调度：SIMT 的假象、Divergence 的代价与 Replay 机制

![A-04 封面：一条指令广播到 32 lane，灰色为 mask](assets/A-04-simt-divergence-cover.png)

## TL;DR（工程结论）

1. **SIMT：程序员看见 32 个线程，硬件按 Warp 锁步发射。** 一条指令广播到 32 lane；寄存器仍是每线程一份。Thread ≠ 绑死一颗 CUDA Core。
2. **Warp 内 `if-else` 是两拍串行 + active mask，不是两路并行。** 教科书常写「约 2×」；本机看 `clock64` **median 比值**，流水线会藏掉一部分。
3. **ITS（Volta 起）解决前进，不解决 Divergence 性能。** 每线程有 PC，自旋不会把整个 Warp 冻死；`if` 该串行还是串行。Ada（RTX 40）也有 ITS，和 Hopper 无关。
4. **Replay ≠ Stall ≠ Divergence。** Stall 是等数据、指令不重发；Replay 是同一条访存指令因 bank / 分裂事务再发一遍。32-way SMEM 冲突是演示，消冲突去 B-02。
5. **口径：lane0 `clock64` median，warmup 后取。** 这不是 kernel 墙钟；event 去 A-08。没有 `sink` 会被 DCE 成 1 cycle，不能当 2× 证据。

## 2. SIMT：一条指令，32 条 lane

程序员写成 `a[i] = b[i] + c[i]`，像 32 个独立小 CPU。SM 里是：Warp Scheduler 取一条指令，广播到 32 个 lane，各人用自己的寄存器。

![图 1：逻辑 32 线程 vs 硬件一条 ADD](assets/A-04-fig1-simt.png)

> 图 1：锁步的是**发射**；数据是私有的。不要把 lane 写成「一线程一颗 Core」。

和 CPU SIMD 的差别：你不用显式写向量类型，编译器 / 硬件把相邻线程捆成 Warp。代价是控制流必须用 mask，不能假设 32 路独立分支便宜。

---

## 3. Divergence：串行 + mask

```cpp
if (threadIdx.x % 2 == 0) A();
else B();
```

硬件不会让 A、B 同时铺满 32 lane。先让偶数 lane 跑 A（奇数 mask 掉），再让奇数跑 B。两条路径的延迟相加。

![图 2：if-else 两拍，不是双发射](assets/A-04-fig2-divergence.png)

> 图 2：灰色 lane 仍占着 Warp 的发射槽，只是不写结果。

「约 2×」只在两条路径算力接近、没有被别的 Warp 藏住时像教科书。本机以示例打印的 median 比为准，**不要把 2.0× 写进结论当实测**。

Predication / 把短分支收成 `cond ? a : b` 能少一次串行；长函数、不同访存模式收不回去。别在 Hello 里上全套 branchless。

---

## 4. ITS：活得下去，不是跑得更快

Volta 起 Independent Thread Scheduling：Warp 内每条线程有自己的 PC。Pascal 及更早，一个线程卡在自旋上，整个 Warp 的 PC 可能一起停，`__syncthreads()` 对侧永远走不到 → 死锁。

![图 3：ITS 解的是前进；if 仍然串行](assets/A-04-fig3-its.png)

> 图 3：右边不是 MIMD。Ada / Hopper / Blackwell 都从 Volta 继承 ITS。RTX 40 有 ITS，**不是因为 Hopper**。

ITS **没有**把 Divergence 的两拍变成一拍。它只保证：等锁的人不必把已经走完分支的人冻死。

不要从网上抄「Warp 内 mutex + `__syncthreads`」当教材示例去跑。正确性用 lock-free / 明确的 warp 原语（C-01），不要靠 ITS 当设计目标。

## 5. Replay：同一条指令再发一遍

| | Divergence | Stall | Replay |
|---|---|---|---|
| 触发 | 控制流分叉 | 操作数没到 | 一次发射没做完（bank、部分内存分裂） |
| 硬件 | 两拍 mask | 等，指令不重发 | **同一条指令再 issue** |
| 本章演示 | 奇偶 `if` | 不测 | stride-32 SMEM |

![图 4：三种停法不要混](assets/A-04-fig4-replay.png)

> 图 4：Nsight 里的 replay 计数不是「又 divergence 了一次」。

32-way bank：32 个线程打同一个 32-bit bank，硬件把这一拍拆成最多 32 次发出。教科书写 32×；流水线和其它 Warp 会藏掉一块，本机常见远小于 32。怎么 padding / swizzle 去 **B-02**，本章只证明「冲突会重放」。

Memory divergence：Warp 还在锁步，但 32 个地址散到很多事务。它常和 Replay 一起出现，**不等于** Replay。合并规则正文在 B-01。

## 6. 怎么跑

前置与导读相同。在 `build/` 里：

```bash
cmake .. -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=native
cmake --build . --parallel --target 01_cuda_basics_04_warp_divergence
./bin/01_cuda_basics_04_warp_divergence
```

两组实验，都是 `<<<1, 32>>>`，warmup 后 **median of 21** 次 lane0 `clock64`：

| 对比 | 看什么 | 不要读成 |
|---|---|---|
| 无分支 vs 奇偶 `if` | Divergence 形状 | kernel 墙钟、2.0× 账单 |
| SMEM stride=1 vs stride=32 | Replay 形状 | 已做完 B-02；32.0× 账单 |

结果写回 `sink`，避免再被 DCE 成 1 cycle。打印 GPU 名和 `sm_XX`。

Windows 输出目录见 [`examples/01_cuda_basics/README.md`](https://github.com/Yapeng-Gao/AI-System-Performance-Lab/blob/main/examples/01_cuda_basics/README.md)。

## 8. SOP + 误区

1. 先跑示例，看 CC ≥ 7.0（有 ITS）。更老的卡只谈 Divergence / Replay，别谈 ITS 救命。
2. 比值远小于 2 或远小于 32：先查有没有 DCE、有没有 warmup，再谈「硬件藏延迟」。
3. 要消 bank：停，去 B-02。要合并访问：去 B-01。
4. 热路径计时改 CUDA event（A-08），不要把 `clock64` 包住一次 launch。

| 误区 | 纠正 |
|---|---|
| 32 线程 = 32 颗独立 CPU | SIMT 锁步发射；见图 1 |
| ITS 让 `if-else` 并行 | 只保证前进；性能仍两拍 |
| RTX 40 的 ITS 来自 Hopper | Volta 起；Ada sm_89 |
| replay 高 = divergence | 图 4；bank 演示 ≠ 分支 |
| 测到 1 cycle 所以没代价 | 旧代码被优化光了；看 sink + median |
| 32-way 必须是 32× | 形状对即可；处方在 B-02 |

## 9. 小结与下一章

Warp 用一条指令喂 32 lane；分叉就 mask 着串行。ITS 让人别互相卡死，不让人白得并行。Replay 是访存没一次做完时的重发。
