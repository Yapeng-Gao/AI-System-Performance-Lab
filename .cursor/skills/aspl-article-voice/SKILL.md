# ASPL 专栏文风（去 AI 味，保留工程骨架）

面向本仓库 **工程索引型** 中文专栏。吸收 [stop-slop](https://github.com/hardikpandya/stop-slop) 的检测维度，**明确否决**会破坏专栏的禁令（禁表格 / 禁编号 / 强行口语鸡汤）。

配套词表：[phrases.md](phrases.md) · 写稿主流程仍以 `aspl-cuda-article` 为准。

## 何时启用

- 写/改 `article/**/*.md` 的**散文段**（承接段、机制叙述、怎么读、小结）
- 用户说：去 AI 味、润色、文风、humanize、读起来像套话
- `aspl-cuda-article` §4 正文落盘后的 **文风自检 pass**

**不要**对本 skill 重写：`.cu`、CSV、命令块、参考文献条目、决策表单元格里的术语。

## 与通用 stop-slop / 中文去 AI 味的冲突裁决

| 外来规则常见要求 | ASPL 裁决 |
|---|---|
| 禁止 Markdown 表 / 决策表 | **拒绝**——决策表、mode 表、实测表是产品 |
| 禁止「第一、第二」类编号 | **部分拒绝**——SOP / 误区清单 / TL;DR 编号保留；散文里少用「首先其次最后」串联 |
| 禁止冒号 | **拒绝**——表头、`mode:`、图注可用冒号 |
| 禁止加粗 | **收紧不禁止**——只加粗判停词、本机关键数字、关键 API；整句加粗禁止 |
| 灌口语（说真的 / 太离谱了） | **拒绝**——工程专栏用干脆书面语，不是公众号腔 |
| 砍掉所有列表 | **拒绝**——误区表、SOP、扩展阅读出口保留 |
| 删 em-dash / 少用破折号 | **采纳**——中文少用长破折号卖戏剧感；用句号拆开 |
| 砍 filler / 假深刻 / 对称排比 | **采纳** |

一句话：**表与命令是骨架；骨架之间的叙述要像人写的技术笔记。**

## 写作立场（散文段）

1. **先给可执行结论，再解释**——读者是来查处方的，不是来听开场白的。
2. **一句一个动作**：谁（你/kernel/该指令）做什么；少「这体现了…」「其本质是…」。
3. **具体**：点名 API、mode、metric、本机数字；禁止「显著提升」「较好效果」无锚点。
4. **节奏有起伏**：长短句交错；连续三句同长度就改一句。
5. **信任读者**：少「需要注意的是」「不难发现」；边界用表格说清即可。
6. **有判断**：该上 / 别上 / 回哪章——不要「各有优劣」收尾空转。
7. **已发稿不是免死金牌**：发现套话照样改；以本 skill + 实测为准。

## 禁止（中文套话优先）

完整列表见 [phrases.md](phrases.md)。高频必砍：

- 综上所述 / 总而言之 / 由此可见 / 不难发现 / 值得注意的是 / 需要指出的是
- 在当今…背景下 / 随着…的发展 / 在…的浪潮中
- 本质上 / 深层次 / 赋能 / 助力 / 闭环 / 抓手 / 打造 / 落地生花
- 不仅…而且…（假递进） / 不是…而是…（连续堆叠）
- 让我们来看看 / 接下来我们将 / 本节将详细介绍
- 英语残留：delve、tapestry、landscape、robust、leverage、game-changer、it's worth noting

## 允许且应保留的结构

- 文首引用块（承接上章）
- **TL;DR** 编号列表（有本机数或明确待测）
- 边界表 / 决策表 / mode 表 / 实测表
- 短 ASCII；图 + 一行图注
- fenced code（命令与内核片段）
- §8 SOP 步骤列表；误区两列表
- §7 短出口；§10 分层参考文献

## 操作流程

```text
1. 只圈「散文段」（跳过表、代码、参考文献行）
2. 对照 phrases.md 删套话；拆破折号戏剧句
3. 把空话换成：API / mode / 数字 / 「回 B-xx / 去 C-xx」
4. 自检五维（每维 1–10；总分 <35 必须再改散文）
5. 确认骨架表与命令未被「润色」弄乱
```

### 五维（改编自 stop-slop）

| 维 | 问 | ASPL 读法 |
|---|---|---|
| 直接性 | 在陈述还是在宣布？ | 有没有「本文将」「让我们」 |
| 节奏 | 像节拍器吗？ | 是否句句一样长、排比三连 |
| 信任 | 是否手把手说教？ | 「值得注意」「不难发现」 |
| 真实感 | 像工程师笔记吗？ | 还是像生成式科普 |
| 密度 | 还能删吗？ | 删后信息是否不变 |

## 改写示例（语气）

**差**

> 值得注意的是，在当今 GPU 编程实践中，合理使用 warp 原语能够显著提升性能。接下来我们将深入探讨其本质。

**好**

> 同 warp 内交换数据，优先 `__shfl_*_sync`，少走「STS → bar → LDS」。收益看 `--mode sweep` 的 `shfl/smem`，不要先背 API 清单。

**差**

> 这种方法各有优劣，需要根据实际情况权衡利弊，从而做出最优选择。

**好**

> float 走 shfl；sm_80+ 的 32-bit int 再试 `__reduce_*_sync`。整 device 规约去 Module D，本章停在 block partial。

## 反模式

- 为去 AI 味拆掉决策表 / TL;DR / 实测表
- 改成公众号口语或鸡汤金句
- 只改标点、不删空信息句
- 把「待测」写成假装有数的模糊夸奖
- 与 `aspl-cuda-column` 硬约束冲突时服从硬约束（证据口径优先）
